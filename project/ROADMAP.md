# MarkEdit 开发计划

> 2026-11-08 · 个人作品项目 · 先本地应用，再可复用组件。阶段状态以验收结果为准。

## 1. 项目定位

MarkEdit 是一款使用 React 和 TypeScript 构建的 Markdown 工作台，面向撰写技术笔记、README 和博客草稿的开发者。项目包含可直接使用的个人写作工作台，以及可嵌入业务项目的 React 编辑器组件。发布前检查 npm 名称和品牌冲突。

首版不做账号、云同步、多人协作、AI、富文本 WYSIWYG 和移动端原生应用。这些会稀释个人项目的编辑器技术深度。

## 2. 产品需求与核心体验

- 面向 Markdown 源码写作，提供实时预览、格式工具栏、搜索替换和撤销/重做。
- 以模块化组件组织编辑器、预览、导航和文档存储，避免将 UI、编辑状态和持久化耦合在单一模块中。
- 组件使用 React props、ESM 和显式扩展配置，工作台使用 IndexedDB 管理文档并提供本地备份。
- 支持 GFM、目录导航、图片回调、公式、图表、主题、只读和可配置工具栏。
- 围绕文档安全、编辑事务和数据恢复建立回归测试，并明确记录兼容范围和未完成验收项。

## 3. 技术方案和取舍

| 层       | 选择                                          | 理由                                                   |
| -------- | --------------------------------------------- | ------------------------------------------------------ |
| 应用     | React 19 + TypeScript strict                  | 受控数据流、可复用组件与类型化 API                     |
| 工程     | Vite + npm lockfile                           | 编辑器工作台没有首屏 SEO/SSR 需求，先降低部署复杂度    |
| 编辑引擎 | CodeMirror 6 + React 适配层                   | Markdown 源码编辑、事务、撤销、搜索、选区和扩展能力    |
| 预览     | react-markdown + remark-gfm                   | AST 渲染、标准 Markdown 和 GFM；默认不执行原始 HTML    |
| UI       | CSS 变量 + Lucide；复杂浮层阶段再引入 Radix   | 先建立完整设计令牌，避免为了组件库增加无用依赖         |
| 状态     | React state；编辑器持有光标与撤销历史         | 第一阶段不需要全局状态库，避免每次输入同步整个应用模型 |
| 持久化   | MVP 单草稿 localStorage；多文档阶段 IndexedDB | 小步交付；存储故障必须显式反馈                         |
| 测试     | Vitest；后续 Playwright 用户流程              | 重点验证数据恢复、内容安全和真实编辑行为               |
| 扩展     | KaTeX、Mermaid 按需加载                       | 公式/图表不进入基础首屏包                              |

官方资料：[Vite](https://vite.dev/guide/)、[react-markdown](https://github.com/remarkjs/react-markdown)、[CodeMirror](https://codemirror.net/)。依赖实际解析版本见 package-lock.json，主版本升级单独评估。

## 4. UI 方向

暖白画布、墨绿色强调色、细分隔线、少量圆角；左侧轻量导航、中间编辑/预览、右侧后续目录。正文阅读优先，工具栏只放高频操作。支持浅色/深色、纯编辑/分屏/纯预览、窄屏堆叠。所有图标按钮提供名称、键盘焦点和按下状态。

## 5. 模块边界

```text
src/
  components/MarkdownEditor.tsx  # 受控 value/onChange，编辑事务，工具栏
  components/MarkdownPreview.tsx # Markdown -> React；不依赖存储
  lib/draft.ts                  # 草稿结构、验证、持久化边界
  App.tsx                       # 工作台、导入导出、保存状态
  styles.css                    # 设计令牌与响应式布局
project/                        # 计划、验收和架构决策
```

P4 已拆出 `packages/editor`；工作台保留根目录入口，独立消费项目放在 `examples/react-consumer`。它使用独立依赖树安装 tarball，便于检验真实包边界。

### P1 · 可运行编辑闭环（1 周，已实现）

- React + TS + Vite 工程；CodeMirror 编辑、GFM 预览。
- 加粗、斜体、标题、引用、列表、链接、代码、表格插入；保留原生撤销/搜索。
- 编辑/分屏/预览视图，浅深主题，中文 UI，响应式。
- 单草稿自动保存、刷新恢复、Markdown 文件导入导出；导入保护未保存数据；存储失败反馈。
- 验收：输入改变预览；选区格式化可撤销；刷新恢复；中文导入导出内容不变；危险 HTML 不执行；构建与关键回归测试通过。

### P2 · 个人知识工作台（1–1.5 周，已实现）

### P3 · Markdown 扩展与编辑体验（已实现，2026-11-09）

功能与基准已完成；长文最终重渲染约 171ms，性能验收保留优化项；真实上传后端未接入。运行 `npm run benchmark` 可复现本地性能测量。

- KaTeX 公式、Mermaid 图表、预览代码高亮，按需分包；渲染错误就地显示。

## 7. 风险与处理

- 数据：localStorage 仅用于单草稿；捕获配额/权限异常；损坏数据不静默覆盖；多标签冲突在 P2 处理。
- 安全：默认不启用原始 HTML；若后续开启，需明确 sanitize schema；图片会向外部 URL 发请求，后续增加隐私控制。
- 性能：避免整个文档列表随击键写入；预览延后调度；公式/图表懒加载；先测再做 Worker/虚拟化。
- 兼容：保持 Markdown 源码可移植，明确列出支持的扩展语法，不承诺兼容所有变体。
- 范围：优先把编辑、恢复、导出打磨可靠，云端与 AI 作为 v2 选题。
